# 요구사항 문서 — CapCut 파리티 및 버그 수정

## 개요

MovieCut(Swift, macOS/iOS 영상 편집기)의 잔여 결함을 수정하고, CapCut 대비 기능·화면 격차를 닫는다.

이 문서의 격차 목록은 **저장소의 기존 갭 분석 문서를 신뢰하지 않고 코드에서 직접 재측정**했다. 이유는 §1에 있다.

### 범위

| 트랙 | 포함 |
|---|---|
| 버그 | 코드에서 재현 근거가 확인된 결함 |
| 화면 파리티 | CapCut 대비 부재가 확정된 UI 표면 |
| 배선 격차 | Core에 구현돼 있으나 App에서 호출 0회인 기능 |
| iOS 파리티 | macOS와 동등하지 않은 iOS 경로 |

### 범위 제외 (Non-Goals)

- **필터·이펙트·전환 콘텐츠 볼륨 추격.** CapCut은 수백 종을 내장하지만 현재 전환 12 / 이펙트 18 / 텍스트템플릿 14 / 스티커 22 / SFX 12는 의도적 큐레이션 전략이다. "전부 맞춘다"의 대상에서 제외하고, 필요하면 별도 스펙으로 다룬다.
- **캡처 입력**(카메라 / 화면 녹화 / Continuity Camera). 범위가 크고 착수 전 제품 결정이 필요하다.
- **Metal 전면 재작성.** 성능 베이스라인상 병목이 아니다.
- **서명·공증·배포 파이프라인.** 출시 차단 요소이지만 CapCut 파리티와 무관하므로 별도 추적한다. (`scripts/release.sh` 부재 확인됨)
- **네트워크 접근 도입.** `App/MovieCutMac/MovieCutMac.entitlements`가 네트워크 entitlement를 의도적으로 제외하고 있고, 그 주석이 이유를 "the app is fully offline / on-device (S8)"로 명시한다. 이것이 앱의 프라이버시 주장과 `PrivacyInfo.xcprivacy`의 근거다. **이 스펙의 어떤 요구사항도 `com.apple.security.network.client`를 요구하지 않는다.** 상세는 요구사항 10.

## 1. 왜 문서를 신뢰하지 않는가 (실측 기준선)

`docs/` 아래 갭 분석 문서들이 지시하는 작업 상당수가 **이미 완료돼 있다.** 문서를 그대로 따르면 끝난 일을 다시 한다.

코드 직접 확인 결과 (grep / 파일 열람 기준, 빌드·테스트 미실행):

| 문서가 주장한 격차 | 실제 코드 상태 | 근거 |
|---|---|---|
| STT가 애플 서버로 폴백 (S8) | **해소됨** | `SpeechTranscriptionProvider.swift:129` — `requiresOnDeviceRecognition = true` 고정 |
| 스키마 마이그레이션 부재 (S1) | **해소됨** | `Sources/MovieCutCore/Storage/ProjectSchemaVersioning.swift` 존재 |
| security-scoped bookmark 0건 (S2) | **해소됨** | `App/MovieCutMac/Media/SecurityScopedAccess.swift`, `PlaybackEngine`·`ExportEngine`이 `beginScope` 호출 |
| entitlements 0개 (S3) | **해소됨** | `MovieCutMac.entitlements`, `MovieCutiOS.entitlements` 양쪽 존재 |
| 프록시 소비 0회 (B-I7) | **해소됨** | `PlaybackEngine` 소비 + `InspectorExportSection` 해상도 피커 + `TimelineView.clipProxyBadge` |
| 카라오케 자막 공백 유실 (R1, P0) | **해소됨** | `TextOverlayPixelProcessor.karaokeAttributedText`가 원본 문자열에 색만 입힘, 주석도 교정됨 |
| 속도 커브 프리셋 0파일 (B-F2.4) | **해소됨** | `InspectorBasicSection.swift:20` `SpeedCurvePreset` + 프리셋 3종 이상 |
| 현지화 카탈로그 0개 (B-U6) | **부분 해소** | `App/MovieCutMac/Localizable.xcstrings` 존재 (Mac 전용) |
| 열 상태 기반 프록시 강등 (S7) | **해소됨** | `ProxyBadgeState.thermalActive`, `ThermalProxyDowngradeTests` |
| J/K/L·툴 모드·⌘스크롤 줌 (S9) | **부분 해소** | `EditTool.swift`, `ShuttleRate`, `TimelineScrollZoomReader.swift` |
| OSLog 구조화 로깅 (S10) | **해소됨** | `App/MovieCutMac/AppLog.swift` |
| 앱 아이콘·번들 메타 (S4) | **해소됨** | `project.yml`의 `MARKETING_VERSION`·`ASSETCATALOG_COMPILER_APPICON_NAME`, 양 타깃 `Assets.xcassets` |

이 부채 자체를 **요구사항 16**으로 정식 등재했다. 낡은 지시서가 남아 있으면 다음 세션이 완료된 작업에 다시 착수한다 — 이 문서를 쓰는 동안 실제로 그 위험이 발생했다.

### 미검증 사항 (정직하게 분리)

- `swift build` / `swift test` / `xcodebuild`를 **실행하지 않았다.** 이 문서의 어떤 숫자도 빌드·테스트 결과가 아니다. 착수 세션이 직접 측정해야 한다.
- iOS는 이 호스트에서 컴파일 불가로 보고돼 있다(iOS 26.5 플랫폼 미설치). 확인하지 않았다.

## 2. 판정 규율

이 스펙의 모든 수용 기준에 공통으로 적용한다.

1. **StaticContract(소스 문자열 존재 검사)로 수용 기준을 대체 금지.** 저장소 테스트 파일의 다수가 이 방식이며, 통과 수치가 동작 신호가 아니다. 새 StaticContract를 추가하지 않는다.
2. **렌더링 관련 기능은 preview와 export를 같은 timestamp에서 동시에 증거로 제시한다.** 과거에 메인 preview가 프로젝트 합성을 쓰지 않아 "타임라인에서 본 것과 export 결과가 다른" 상태가 있었고, 그 기간의 파리티 판정이 신뢰를 잃었다.
3. **자가보고 수치 금지.** 보고하는 모든 숫자는 그 세션에서 직접 실행한 명령의 출력이어야 한다.
4. 시간 매핑을 건드리는 작업은 timeline↔source 일관성을 반드시 검증한다. 이 영역은 과거에 깨져 있던 전례가 있다.

## 3. 요구사항

### 요구사항 1 — 영어 로케일에서 한국어 접근성 레이블이 읽히는 결함

**사용자 스토리:** 영어 로케일 사용자로서, VoiceOver가 타임라인 조작 요소를 영어로 읽어주기를 원한다. 지금은 한국어를 읽는다.

**근거 (확인됨):** `App/MovieCutMac/Localizable.xcstrings`의 `en` 값 3건이 한국어다 — `%@ 오른쪽 트림 핸들`, `%@ 왼쪽 트림 핸들`, `%@ 클립 추가 영역`. 호출부는 `TimelineView.swift:788, 941, 950`. `NSLocalizedString`의 키 자체가 한국어인 호출부가 다수 있고 대부분은 카탈로그가 영어로 번역했으나 이 3건이 빠졌다.

**수용 기준**
1. WHEN 앱이 영어 로케일로 실행되면 THEN 시스템은 접근성 레이블에 한글을 0건 노출해야 한다.
2. WHEN 앱이 한국어 로케일로 실행되면 THEN 기존 한국어 문구는 변경되지 않아야 한다.
3. 코드가 사용하는 키 집합과 카탈로그 키 집합은 계속 일치해야 한다.
4. IF 한국어 키를 영어 키로 바꾸는 근본 수정을 선택하면 THEN 코드↔카탈로그 대조를 자동화된 방법으로 수행하여 누락이 없음을 보여야 한다.

---

### 요구사항 2 — preview ↔ export 동작 파리티 재확인

**사용자 스토리:** 편집자로서, 타임라인에서 본 결과가 export 결과와 같기를 기대한다.

**근거:** 과거 메인 preview가 프로젝트 합성 경로를 쓰지 않고 선택된 원본 asset을 직접 재생했고, magnetic compaction이 모든 트랙에 무차별 적용됐으며, 배속/ramp의 timeline↔source 시간 일관성이 깨져 있었다. 각각 수리됐지만 그 기간에 내려진 "동등" 판정이 동작 확인 없이 부여됐다.

**수용 기준**
1. WHEN split / trim / move / delete / ripple 각각을 수행한 뒤 export하면 THEN 같은 timestamp의 preview 캡처와 export 프레임이 허용 오차 내에서 일치해야 한다.
2. WHEN 배속 / 램프 / 역재생 / 프리즈를 적용하면 THEN 1과 동일한 기준을 만족해야 한다.
3. 파리티 검증은 프레임 비교에 더해 **duration 비교**를 포함해야 한다 (프레임만 맞고 길이가 틀린 경우를 잡기 위함).
4. WHEN 파괴적 편집 후 undo를 왕복하면 THEN 프로젝트 상태가 편집 전과 동일해야 한다.
5. 각 항목은 실행 산출물(명령 출력, 생성된 파일, 프레임 샘플)로 증명되어야 하며 소스 문자열 검사로 대체할 수 없다.
6. 이 요구사항은 두 단계로 나뉜다 (`design.md` §2.1). 순환 의존을 피하기 위한 분할이다.
   - **2a 기준선 확립** — 커버리지를 늘리지 않고 현재 시나리오를 그대로 실행해 실측치를 기록하고, 허용 오차 정책과 duration 단언을 확정한다. **요구사항 4 · 7 · 8의 게이트는 여기까지다.**
   - **2b 커버리지 확장** — trim / move / ripple / 역재생 / 프리즈 / undo 왕복 시나리오와 비후행 삭제 하니스 변경. 요구사항 4 · 7 · 8과 **병행**하며 그것들의 선행이 아니다.
   - 게이트를 통과시키기 위해 허용 오차를 올리지 않는다. 오차 상향은 근거를 남기는 정책 결정이다.

### 요구사항 3 — 홈 화면 / 프로젝트 관리 동선

**사용자 스토리:** 여러 프로젝트를 다루는 사용자로서, 앱을 열면 최근 프로젝트를 보고 골라 들어가고 싶다.

**근거 (확인됨):** `MovieCutMacApp.swift:13`의 `WindowGroup`이 곧바로 `ContentView`(편집기)를 띄운다. `HomeView` / `RecentProjects` 계열 심볼이 코드에 0건. 프로젝트 목록 화면 자체가 없고 File > Open 메뉴만 있다. CapCut 대비 유일한 **구조적 IA 부재**다.

**수용 기준**
1. WHEN 앱을 실행하면 THEN 시스템은 최근 프로젝트 목록(썸네일·이름·수정 시각·길이)을 보여주는 홈 화면을 표시해야 한다.
2. WHEN 사용자가 새 프로젝트를 만들거나 기존 프로젝트를 열면 THEN 시스템은 편집기로 전환해야 한다.
3. WHEN 프로젝트를 저장하면 THEN 최근 목록이 갱신되어야 한다.
4. IF 최근 목록의 항목이 가리키는 파일이 존재하지 않으면 THEN 시스템은 이를 구분해 표시하고 목록에서 제거할 수단을 제공해야 한다.
5. 최근 목록은 App Sandbox에서 재시작 후에도 열릴 수 있어야 한다 (security-scoped bookmark 사용).
   - **기존 `SecurityScopedAccess`는 그대로 재사용할 수 없다.** 이 타입은 `MediaAsset`에 결합되어 있고(`resolveBookmark(for: asset)` / `beginScope(for: asset)` / `withSecurityScope(for: asset)`), URL을 받는 것은 `makeBookmark(for url:)` 하나뿐이다. 프로젝트 파일 URL을 다루려면 **URL 수준 오버로드 추가 + 기존 asset 버전이 그것을 호출하도록 리팩터**가 필요하다 (`design.md` §4.2).
   - bookmark 처리 경로를 복제해 두 번째 구현을 만들지 않는다. 이 타입이 해당 라이프사이클의 단일 소유자라는 성질을 유지한다.
6. WHEN 헤드리스 / UI 테스트 하니스로 실행하면 THEN 기존처럼 편집기로 직행하여 E2E가 회귀하지 않아야 한다.
7. WHEN 편집기에서 홈으로 돌아가는데 저장되지 않은 변경이 있으면 THEN 시스템은 저장 여부를 확인해야 한다.

### 요구사항 4 — 클립 블렌딩 모드

**사용자 스토리:** 오버레이를 합성하는 사용자로서, 클립에 Multiply / Screen / Overlay / Soft Light 같은 블렌딩 모드를 지정하고 싶다.

**근거 (확인됨):** 사용자 노출 0. 코드의 블렌딩 관련 문자열은 `VisualEffectPixelProcessor.swift:178,188` 등의 `CISoftLightBlendMode` / `CIOverlayBlendMode`로, 필터 내부 구현명일 뿐이다. `Clip`에 블렌딩 필드가 없고 UI도 합성 분기도 없다. 다중 트랙 레이어링 자체는 이미 동작한다.

**수용 기준**
1. WHEN 사용자가 클립을 선택하면 THEN 인스펙터에서 블렌딩 모드를 선택할 수 있어야 한다.
2. WHEN 블렌딩 모드를 적용하면 THEN preview와 export가 동일한 합성 결과를 만들어야 한다.
3. WHEN 모드가 기본값(normal)이면 THEN 이 기능 도입 전후의 export 프레임이 픽셀 동일해야 한다 (회귀 없음).
4. WHEN 블렌딩 필드가 없는 기존 프로젝트 파일을 열면 THEN 기본값으로 해석되어 정상 로드되어야 한다. 이는 픽스처 테스트로 고정한다.
5. WHEN 불투명도와 블렌딩을 함께 적용하면 THEN 두 속성이 함께 반영되어야 한다.
6. 각 모드는 골든 픽셀 테스트로 검증되어야 한다.
7. **이 요구사항의 완료 범위는 macOS다.** iOS 합성기는 공유 프로세서를 경유하지 않고 inline 재구현을 쓰므로, iOS 블렌딩은 요구사항 12(공유 프로세서 전환) 이후로 이관한다. macOS만 완료된 상태를 보고할 때 그 한계를 함께 적는다.
8. 골든 픽셀 판정은 `design.md` §2.2가 정한 정책(소프트웨어 렌더러 기준, 채널당 오차 2, skip 금지)을 따른다.

### 요구사항 5 — 프리뷰 품질(성능 우선) 선택

**사용자 스토리:** 무거운 프로젝트를 편집하는 사용자로서, 프리뷰 해상도를 낮춰 반응성을 확보하고 싶다.

**근거 (확인됨):** `PreviewQuality` 계열 심볼 0건. 프록시 재생 토글과 프록시 해상도 선택은 있으나(요구사항 아님, 이미 완료) CapCut의 "Performance Priority"에 해당하는 프리뷰 렌더 해상도 수동 선택은 없다.

**수용 기준**
1. WHEN 사용자가 프리뷰 품질을 선택하면 THEN 프리뷰 렌더 해상도가 그에 맞게 변경되어야 한다.
2. WHEN 프리뷰 품질을 낮추면 THEN export 결과 해상도는 영향을 받지 않아야 한다.
3. 선택 상태는 프로젝트와 함께 저장·복원되어야 한다.
4. 이미 존재하는 프록시 자동 강등(열 상태 기반) 표시 체계와 충돌하지 않아야 하며, 현재 화질이 왜 낮은지 사용자가 구분할 수 있어야 한다.

---

### 요구사항 6 — 자막 export 포맷 확장 (VTT / ASS)

**사용자 스토리:** 자막을 다른 플랫폼에 올리는 사용자로서, SRT 외의 포맷으로 내보내고 싶다.

**근거 (확인됨):** SRT만 존재. `WebVTT` / `AdvancedSubStation` 계열 심볼 0건.

**수용 기준**
1. WHEN 사용자가 자막 export 포맷으로 WebVTT를 선택하면 THEN 시스템은 유효한 `.vtt` 파일을 생성해야 한다.
2. WHEN ASS를 선택하면 THEN 유효한 `.ass` 파일을 생성해야 한다.
3. 생성된 파일의 타이밍은 타임라인의 자막 클립 시각과 일치해야 한다.
4. 기존 SRT export 동작은 변경되지 않아야 한다.
5. 검증은 생성된 파일의 실제 파싱 또는 재생기 확인으로 이뤄져야 한다.

### 요구사항 7 — 컴파운드 클립 (중첩 시퀀스)

**사용자 스토리:** 복잡한 편집을 하는 사용자로서, 여러 클립을 하나로 묶어 단일 단위처럼 다루고 싶다.

**근거 (확인됨):** `CompoundClip` / `NestedSequence` 계열 0파일. 인접 개념인 클립 그룹(`GroupClipsCommand`)은 이미 있고 복사/붙여넣기가 그룹 id 재매핑을 처리하므로 선행 인프라로 재사용할 수 있다.

**수용 기준**
1. WHEN 사용자가 여러 클립을 선택해 컴파운드로 만들면 THEN 타임라인에 단일 클립으로 표시되어야 한다.
2. WHEN 컴파운드 클립을 이동·트림·복사하면 THEN 내부 구성이 상대적으로 보존되어야 한다.
3. WHEN 컴파운드 클립을 열면 THEN 내부를 편집할 수 있고 편집 결과가 상위 타임라인에 반영되어야 한다.
   - **이 기준은 이 스펙의 필수 완료 조건에서 분리한다.** `design.md` §4.6의 Inc 2에 속하며, 재렌더 무효화 정책이라는 열린 결정에 막혀 있다. Inc 1a~1c(중첩 없는 단일 렌더 단위)만으로 나머지 수용 기준이 닫히고 CapCut 대비 핵심 격차도 닫힌다.
   - Inc 1은 내부 편집이 없으므로 "컴파운드 클립 완성"으로 보고하지 않는다.
4. WHEN 컴파운드 클립을 해제하면 THEN 원래 클립들이 복원되어야 한다.
5. preview와 export가 컴파운드 클립을 동일하게 합성해야 한다.
6. 컴파운드를 포함한 프로젝트의 저장·로드 왕복이 무손실이어야 하며, 컴파운드가 없는 기존 프로젝트도 계속 열려야 한다.
7. 컴파운드 생성/해제는 단일 undo 단위여야 한다.

### 요구사항 8 — slip / slide 트림 도구

**사용자 스토리:** 정밀 편집을 하는 사용자로서, 클립의 타임라인 위치를 유지하며 소스 구간만 이동(slip)하거나, 인접 클립 경계를 밀며 이동(slide)하고 싶다.

**근거 (확인됨):** `slip` / `rollEdit` 계열 심볼 0건. 동일 작업지시서의 다른 항목(J/K/L 셔틀, 선택/블레이드 툴 모드, ⌘+스크롤 줌)은 이미 구현됐다 — `EditTool.swift`, `ShuttleRate`, `TimelineScrollZoomReader.swift`. 따라서 이 요구사항은 S9의 **잔여분**이다.

**수용 기준**
1. WHEN 사용자가 slip 조작을 하면 THEN 클립의 타임라인 범위는 유지되고 소스 구간만 이동해야 한다.
2. WHEN 사용자가 slide 조작을 하면 THEN 해당 클립이 이동하고 인접 클립의 경계가 그에 맞춰 조정되며 전체 길이는 유지되어야 한다.
3. 두 조작은 기존 `ClipTrimMath` / `ClipTimeMapping`을 확장해 구현해야 하며 새로운 시간 계산 체계를 병렬로 만들지 않아야 한다.
4. WHEN 조작 후 export하면 THEN preview와 결과가 일치해야 한다 (요구사항 2의 기준 적용).
5. 소스 구간 경계를 넘는 조작은 클램프되어야 하며 잘못된 상태를 만들지 않아야 한다.
6. 각 조작은 단일 undo 단위여야 한다.

### 요구사항 9 — 보컬 분리 앱 배선

**사용자 스토리:** 음악에서 보컬을 제거하거나 분리하고 싶은 사용자로서, 앱 UI에서 이 기능을 쓰고 싶다.

**근거 (확인됨):** `Sources/MovieCutCore/Audio/VocalSeparationService.swift`에 `CenterChannelVocalSeparator`(mid/side DSP, `removeVocals` / `isolateCenter`, ML 확장용 `AudioStemSeparator` 프로토콜)가 실재하고 단위 테스트도 있으나, **App 호출 0회**다. 저장소 문서에 dead code 위반 사례로 반복 등재됐고 여전히 죽어 있다. 배선 전례로 `NoiseReductionService`(오프라인 렌더 → 파일 생성 → 클립 소스 교체)가 있다.

**수용 기준**
1. WHEN 사용자가 오디오 클립을 선택하면 THEN 인스펙터에서 보컬 제거 / 센터 분리와 강도를 지정해 적용할 수 있어야 한다.
2. WHEN 적용하면 THEN 결과가 preview와 export 양쪽에서 들려야 한다.
3. 적용은 단일 undo 단위여야 한다.
4. IF 입력이 스테레오가 아니면 THEN 시스템은 명시적인 오류 사유를 사용자에게 알려야 한다.
5. 검증은 실제 오디오 측정으로 이뤄져야 한다 — 센터 팬 성분의 에너지가 유의미하게 감소하고 사이드 성분은 유지됨을 수치로 보인다. 소스 문자열 검사로 대체할 수 없다.

### 요구사항 10 — 미배선 Core 서브시스템 거취 결정

**사용자 스토리:** 이 저장소를 유지하는 사람으로서, App에서 호출되지 않는 코드가 감사마다 노이즈로 재등장하지 않기를 원한다.

**근거 (확인됨):** `App/MovieCutMac/MovieCutMac.entitlements`에 네트워크 entitlement가 **의도적으로 없다** — 주석이 이유를 "the app is fully offline / on-device (S8)"로 명시한다. 그런데 `Sources/MovieCutCore/AI/ClaudeEditingProvider.swift`의 `URLSessionClaudeTransport`는 `URLSession`으로 `https://api.anthropic.com/v1/messages`에 POST한다. 즉 이 코드는 **샌드박스에서 동작할 수 없고**, 동작하게 만들려면 네트워크 접근을 추가해야 하는데 그것은 `PrivacyInfo.xcprivacy`의 기재 내용, 그리고 거짓 오프라인 주장을 없애려고 수행된 S8 수정과 정면으로 충돌한다. 이 사실이 아래 결정을 좌우한다.

**결정 (이 스펙에서 확정 — 더 이상 열린 질문이 아니다)**

| 서브시스템 | 결정 | 근거 |
|---|---|---|
| `Audio/VocalSeparationService` | **배선** | 온디바이스 DSP이고 CapCut 대비 실제 격차(B-F5.2)에 대응한다 → 요구사항 9가 담당 |
| `AI/AIEditingProvider` | **유지 + 배선** | `AIEditingProvider` 프로토콜과 `RuleBasedEditingProvider`는 네트워크가 필요 없고 결정론적이며, 기존 `AssistantIntent` / `AssistantCommandParser` 경로를 재사용한다. 이미 존재하는 어시스턴트 UI를 이 프로토콜 경유로 배선한다 |
| `AI/ClaudeEditingProvider` (+ `URLSessionClaudeTransport`) | **삭제** | 네트워크 필수. entitlement 부재로 동작 불가하며, 추가하면 오프라인 주장이 깨진다 |
| `Analysis/StyleTransferProvider` | **삭제** | 실제 스타일 효과는 `VisualEffectPixelProcessor` 계열이 제공한다. 같은 일을 하는 두 번째 구현이다 |
| `Cloud/CollaborationService` | **삭제** | 공유 링크·원격 상태는 네트워크 필수. 위와 동일한 이유로 동작 불가이며 CapCut 파리티 항목도 아니다 |
| `Cloud/VersionHistory` | **삭제** | CapCut 파리티 항목이 아니고 현재 제품 로드맵 슬롯이 없다. 로컬 버전 관리가 필요해지면 별도 스펙으로 신설한다 |
| `Analysis/BackgroundRemovalProvider` | **위양성 기록 후 삭제** | 배경 제거 기능은 `PersonSegmentationCompositor` 경로로 실제 동작한다. 프로바이더만 미사용이므로, 기능 회귀가 없음을 먼저 보인 뒤 프로바이더를 제거한다 |

**수용 기준**
1. WHEN 착수하면 THEN 각 파일의 현재 참조 상태를 먼저 재측정하여 위 표와 일치하는지 확인해야 한다. 불일치가 있으면 표를 갱신하고 결정을 재검토해야 한다.
2. WHEN 삭제를 수행하면 THEN 해당 코드와 그것만을 대상으로 하던 테스트를 함께 제거하고, 삭제 후 빌드와 전체 테스트가 통과함을 실행 출력으로 보여야 한다.
3. WHEN `AIEditingProvider`를 배선하면 THEN 어시스턴트 UI가 이 프로토콜을 경유해야 하고, 오프라인 규칙 기반 경로로 실제 편집 의도가 타임라인에 적용되는 것이 동작 테스트로 확인되어야 한다.
4. **네트워크 entitlement를 추가하지 않아야 한다.** 어떤 작업도 `com.apple.security.network.client`를 필요로 하지 않아야 하며, 필요해지는 순간 그것은 이 스펙 범위를 벗어난 제품 결정이다.
5. 삭제로 인해 CapCut 대비 격차가 새로 생기지 않아야 한다. 삭제 대상이 대응하던 B-ID가 있으면 그 격차가 다른 경로로 이미 충족됨을 보여야 한다.
6. 작업 후 App 호출 0회인 Core 서비스가 남아 있지 않아야 하며, 남는다면 그 이유가 문서에 기록되어야 한다.

### 요구사항 11 — iOS 빌드 및 테스트 인프라

**사용자 스토리:** 이 프로젝트의 개발자로서, iOS 코드가 컴파일되고 테스트되는 것을 확인하고 싶다.

**근거:** iOS 소스가 이 호스트에서 컴파일되지 않는다고 보고돼 있다(iOS 26.5 플랫폼 미설치). iOS 테스트 타깃과 UI 테스트 하니스가 없다고 보고돼 있다. CapCut의 주 사용처가 모바일이므로 이는 기능 격차 이전의 문제다.

**선행 조건 (사용자 조치):** Xcode에서 iOS 플랫폼 설치. 이것 없이는 요구사항 11~14의 어떤 항목도 완료로 처리할 수 없다.

**수용 기준**
1. WHEN iOS 스킴을 빌드하면 THEN 성공해야 하며 그 출력이 증거로 제시되어야 한다.
2. iOS UI 테스트 타깃이 존재하고 시뮬레이터에서 실행되어야 한다.
3. iOS 하니스가 import → export 파이프라인을 실제로 구동하고, 생성된 미디어 파일의 존재와 길이가 외부 도구로 확인되어야 한다.
4. `project.yml` 변경 시 `info:` 블록을 추가하지 않아야 한다 — 손으로 관리되는 `Info.plist`(커스텀 UTI 선언, 마이크 권한)를 덮어쓴다. 변경 전후 `Info.plist` 해시 비교로 덮어쓰기가 없었음을 보여야 한다.
5. CI의 iOS 단계가 실패를 조용히 통과시키지 않아야 한다.
6. IF iOS 플랫폼이 설치되지 않았으면 THEN 요구사항 11~14는 미착수로 남기고 완료로 표시하지 않아야 하며, 요구사항 1~10 · 15 · 16은 그와 무관하게 진행·완료될 수 있어야 한다. 검증되지 않은 iOS 관련 주장을 기록하지 않아야 한다.

### 요구사항 12 — iOS 합성기의 공유 프로세서 전환 (크로마키 / 배경 제거)

**사용자 스토리:** iOS 사용자로서, 크로마키와 배경 제거 결과가 macOS와 같기를 기대한다.

**근거 (확인됨):** `ChromaKeyPixelProcessor` / `PersonSegmentationCompositor` 참조가 `App/MovieCutMac/Export/CustomVideoCompositor.swift`(각각 `:544,546`, `:1085,1091`)에만 있고 iOS 합성기에는 없다. iOS는 inline 재구현을 쓴다.

**수용 기준**
1. WHEN iOS에서 크로마키를 적용하면 THEN Core의 공유 프로세서를 경유해야 한다.
2. WHEN iOS에서 배경 제거를 적용하면 THEN 동일하게 공유 프로세서를 경유해야 한다.
3. 같은 프로젝트를 iOS와 macOS에서 export한 결과를 비교해, **고정된 시뮬레이터 기종·OS 버전 1종**에서 같은 기기 preview↔export 기준선과 **동일한 MAD 허용 오차 내**에 있어야 한다. 특히 매트 축소(edgeShrink)와 softness 파리티를 확인해야 한다 — 과거 이 불일치가 defer 사유였다.
   - 채널당 절대 오차(골든 픽셀 척도)를 크로스 플랫폼 판정에 쓰지 않는다. 두 플랫폼은 서로 다른 Core Image 경로를 탈 수 있고 매트 연산의 부동소수 연산 순서가 달라 픽셀 1:1 불일치가 정상이다. 근거와 정책은 `design.md` §2.2 결정 4.
   - 기종·OS 조합을 결과에 기록한다. 기록 없는 수치는 무효다.
   - 허용 오차 초과는 곧 실패가 아니라 **파리티 격차 보고 대상**이다. 수치와 함께 원인(연산 순서 / 실제 로직 차이)을 구분해 기록한다.
4. inline 재구현은 제거되어야 하며 같은 수식이 두 곳에 남아 있지 않아야 한다.

### 요구사항 13 — iOS two-source 전환 배선

### 요구사항 14 — iOS 현지화

**사용자 스토리:** 한국어를 쓰는 iOS 사용자로서, 앱이 한국어로 표시되기를 원한다.

**근거 (확인됨):** `.xcstrings`가 `App/MovieCutMac/`에만 있다. iOS에는 카탈로그가 없다. 또한 `NSLocalizedString` 래핑이 macOS 소스에서만 확인되므로, **iOS는 문자열 래핑 자체가 선행 작업**이다. 카탈로그만 추가하면 효과가 없다.

**수용 기준**
1. iOS의 사용자 노출 문자열이 현지화 가능하도록 래핑되어야 하며, 착수 시 그 개수를 먼저 측정해 보고해야 한다.
2. iOS 현지화 카탈로그가 존재하고 한국어 번역이 채워져야 한다.
3. 동일한 UI 개념에 대해 macOS 카탈로그와 다른 번역어를 쓰지 않아야 한다.
4. WHEN iOS를 한국어 로케일로 실행하면 THEN 번역이 실제로 표시되어야 하며 이는 실행 증거로 확인되어야 한다.
5. 영어 로케일에서 한글이 노출되지 않아야 한다 (요구사항 1과 동일 기준).

### 요구사항 15 — 검증 신뢰도 부채 정리

**사용자 스토리:** 이 저장소에서 작업하는 사람으로서, 테스트 통과가 동작을 뜻하기를 원한다.

**근거:** 테스트 파일의 다수가 소스 문자열 존재를 검사하는 StaticContract이고, "이 기능이 존재하면 안 된다"를 잠그는 부정 단언이 다수 있다. 후자는 기능 구현을 능동적으로 방해한다. 실제로 iOS 파리티 작업을 막던 부정 단언이 존재했던 전례가 있다. 린트는 비블로킹 상태로 보고돼 있다.

**수용 기준**
1. `docs/` 문서 산문을 단언하는 테스트는 제거되어야 한다. 문서 오타 수정이 테스트를 깨뜨리는 것은 의존 방향이 거꾸로다.
2. 부정 단언은 **결함 고정**(기능 부재를 잠금 → 제거)과 **경계 방향**(계층 침투 방지 → 주석 달아 유지)으로 분류되어야 하며, 분류표와 근거가 제시되어야 한다.
3. 렌더 프로세서에 대한 문자열 단언은 골든 픽셀 테스트로 승격되어야 하며, 승격된 테스트가 실제로 실행됐음(조용히 skip되지 않았음)이 확인되어야 한다.
4. 테스트 수가 줄어드는 것은 정상이며, 줄어든 만큼이 원래 가짜 신호였다. 착수 전후 수치를 실측으로 기록해야 한다.
5. 린트를 오류에 대해 차단(blocking)으로 전환할 수 있는지 판단하고, 가능하면 전환해야 한다. 규칙을 완화하는 경우 그것이 이 코드베이스에서 정당한 이유를 기록해야 한다 — 그냥 끄지 않는다.
6. 이 스펙의 어떤 작업도 새 StaticContract를 추가하지 않아야 한다.

### 요구사항 16 — 낡은 작업지시서 정리 (문서 부채)

**사용자 스토리:** 이 저장소에 새로 합류하는 작업자로서, 문서가 지시하는 작업이 실제로 남아 있는 작업이기를 원한다.

**근거 (확인됨):** §1의 표가 보여주듯 `docs/` 아래 지시서 다수가 **이미 완료된 작업을 지시한다.** 세션 시작 프롬프트까지 포함된 형태라 그대로 실행되기 쉽다. 이 스펙을 작성하는 과정에서 실제로 완료된 항목에 착수할 위험이 발생했고, 코드를 직접 재측정해서야 걸러졌다.

**수용 기준**
1. WHEN 이 스펙의 작업이 완료되면 THEN 관련 지시서(`PRO_SPEC_GAP_WORKORDER_*`, `NEXT_SESSION_WORKORDER_*`, `REVIEW_FINDINGS_WORKORDER_*`, `GAP_ANALYSIS_V13_*`)의 완료 항목이 완료로 표시되거나 문서 전체가 폐기 표시되어야 한다.
2. 완료 표시는 근거(커밋 해시 또는 코드 위치)를 포함해야 한다.
3. 최신 판정으로 가는 **단일 진입점**이 존재해야 하며, 어떤 문서가 최신인지 독자가 추측하지 않아도 되어야 한다.
4. 문서 산문을 단언하는 테스트를 새로 만들지 않아야 한다 (요구사항 15와 동일 규율).

## 5. 착수 전 확인 필요

1. **iOS 플랫폼 설치 여부.** 요구사항 11~14가 여기 막혀 있다. 미설치 시의 처리는 요구사항 11의 수용 기준 6이 정의한다. **이 스펙의 유일한 외부 차단 요소다.**
2. **검증 인프라 실존 확인.** 골든 픽셀 하니스와 접근성 레이블을 읽는 XCUITest 경로가 이 호스트에서 실제로 완주하는지 확인한다. 둘 중 하나라도 못 돌면 그 인프라 구축이 해당 요구사항(4·15 또는 1)의 범위 안이다. `tasks.md` 작업 0이 이것을 담당한다.

### 해소된 항목

- **요구사항 2의 파리티 스크립트 현황** — 확인 완료. `scripts/verify_preview_export_parity.py`는 `probe_duration()`으로 duration을 읽지만 **샘플 timestamp의 범위 초과를 가드하는 용도이고, export 길이가 합성 길이와 일치하는지는 단언하지 않는다.** 따라서 duration 단언 추가가 필요하다는 결론은 유지되며, 그 형태는 `--expect-duration` 옵션이다 (`design.md` §2.1).
- **요구사항 10의 서브시스템 거취** — §3에서 확정됐다. 네트워크 entitlement 부재라는 확인된 제약이 판단을 결정했으므로 재논의 대상이 아니다. 재논의가 필요해지는 유일한 조건은 제품이 네트워크 기능을 공식 채택하는 경우이며, 그것은 별도 스펙이다.
- **골든 픽셀 허용 오차 / 기준 머신 정책** — `design.md` §2.2에서 확정됐다. 기준은 물리 머신이 아니라 소프트웨어 `CIContext`이며, 이는 이미 `GoldenPixelHarness`에 확립되어 있다. 크로스 플랫폼 비교는 골든 척도가 아니라 MAD 척도를 쓴다 (요구사항 12의 수용 기준 3).
