## 이번 회차 개선 실행 증분 (§6-7) — repair 증명 승격(two-tree proof)

**"lock이 말하는 것" → "Git의 과거 두 tree가 fixture와 lock 모두 A→B였음을 독립 증명"**:
1. ancestry(base⊂change·change⊂HEAD) 2. blob을 tree에서 재계산(worktree 불신) 3. **lock 파일을 두 tree에서 직접 판독**(A→B·identity[fixture_id/path/oracle_role] 불변 — lock 사후 조작 통과 불가) 4. union-commit 경계(base..change에서 fixture∪lock 커밋 정확히 1개) 5. update_id 증거 재계산 6. idempotent 3상태+PROVENANCE_CONFLICT(exit 3).
- **검증(E2E)**: 정당 repair(provenance-unit 커밋)→CREATED+verify PASS·lock 사후 조작→UNRECOVERABLE·union 위반(fixture·lock 별도 커밋)→UNRECOVERABLE·재실행→ALREADY_PRESENT·위조 evidence→CONFLICT 3·실 lock 회귀 PASS.
- **검증 중 수리 2건**: ①payload_digest가 idempotent 검사보다 뒤에 정의(순서 이동) ②reason이 정준 동일성에 포함돜 재실행 오판(증거 커밋 기준으로 교정). 테스트 함정 기록: zsh 변수 단어분할(`CI="git -c…"` → 함수로)·E2E 시나리오가 provenance-unit 계약 위반 순서였던 것(초기 3결과는 전부 올바른 UNRECOVERABLE).
