## 46회차 증분 — QAUTO-08 golden identity 테스트 (완결)

**완료 기준 충족**: 3관계 테이블+sequence 순서 사례 PASS·golden digest가 커밋에 고정·확정 도구 명시.

| 단계 | 결과 |
|---|---|
| 운영 canonical 경로 분리 | `canonicalCoreJSON(_:)` 신설 — semanticIdentity는 그 bytes의 SHA256(SeedPromotionSupport.sha256Hex 재사용). 테스트가 운영 정규화 출력을 직접 관찰(테스트 측 재직렬화 아님 — 판정 요건) |
| golden bytes 수작업 작성 | 명세에서 작성(정렬 객체 키·sequence 순서 보존·최소 십진수 — 0.75/0.5는 표현 비애매성 설계) |
| digest 외부 도구 고정 | `shasum -a 256 -b` — 최종 **a27b38f0b2b3f906f2403c0b95f6509bc66cfea1cbc5e19bd43f4a151996cdcf**(168바이트·개행 없음) |
| 테이블 테스트 | ①기준=reviewed bytes+golden digest 일치 ②표면 키 순서+식별자(fixture_id/seed)만 다른 동일 의미=동일 bytes·동일 identity(운영 디코드 경로 투입·테스트 선(先)정규화 없음) ③a=invariant 변경→다름·**③b=sequence 순서 교체→다름(sequence 오정렬 결함 겨냥)**·③c=state 변경→다름 |
| 실측 | **5/5 PASS**(golden 0.001s+기존 4테스트 회귀 0) — `swift test --filter SeedPromotionProductionTests`·실측 2026-10-11 04:10 |

**golden 테스트의 가치 첫 실증(정직 기록)**: 첫 작성분이 FAIL — flat 단일 연관값 enum 인코딩 가정(`{"addMarker":"m1"}`)이 틀렸고 **이 컴파일러의 합성 Codable은 `{"addMarker":{"_0":"m1"}}` 중첩 형태**. golden 테스트가 운영-명세 불일치를 잡아 명세 이해를 교정한 후 reviewed bytes 재확정(154→168바이트·digest 재고정). 운영 출력을 golden에 복사한 것이 아니라 **명세 규칙을 실측으로 확정한 절차** — 이력은 테스트 주석에 기록.
