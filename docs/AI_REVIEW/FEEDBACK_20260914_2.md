## 1. QAUTO-01 3차 구현 — 판정: 조건부 승인(설계와 실질 일치)

승인 설계 4조건 모두 충족 확인(예상 상태 정확 일치·동일 실행 경로·실패 시 실측 금지·결과+provenance 보존). CA-18은 특히 좋음 — "잘못된 입력이 실패한다"가 아니라 과거 문제(25ms 미달 → 검출 0 → degeneracy → 거짓 PASS 가능)라는 **실제 실패 모드를 반복 발화**시키므로 regression control로 적합.

남은 우회 경로 4가지:
1. **stale CONTROL_OK 재사용 방지** — 이전 실행의 CONTROL_OK/로그를 이번 실행 것으로 오인하면 preflight 전체 무력화. run_id·app_commit·driver_sha256·fixture/manifest hash·invocation id가 같은 실행 단위로 묶여야. 실측 허용 조건: `real_measurement_allowed = CA18.control_ok_for_current_run AND CA21.control_ok_for_current_run AND positive_smoke.control_ok_for_current_run`.
2. **문자열 기반 PASS 감지 지양** — 로그 어딘가의 "PASS"와 최종 verdict PASS는 다름. structured result → exit status → 명시적 final marker 순으로 신뢰.
3. **rc 전파 확인** — `runner | tee log`는 tee의 rc를 받으므로 `PIPESTATUS`로 보존 필요. (→ 우리는 이미 `${PIPESTATUS[0]}` 사용 — 처리돼 있음)
4. **컨트롤→실측 상태 오염 차단** — 전행 동일 결과가 좋은 증거지만, 임시·캐시·모델 state 잔류 가능성 차단 유지.

## 2. CA-21 observed 빈 값 — 수용 불가, 명시 상태로 교정(단 판정 방식 유지)

손상 입력의 현재 동작은 FAIL이 아니라 `suite started → 내부 오류/중단 → verdict 미출력 → rc≠0`. 의미상 정확한 기록:

```json
{ "expected_behavior": "REJECT", "observed_execution": "ABORT_BEFORE_VERDICT",
  "exit_code": "nonzero", "suite_started": true, "pass_issued": false, "control_result": "CONTROL_OK" }
```

실행 상태(PASS/FAIL/ABORT/NO_RUN)와 컨트롤 판단(CONTROL_OK/CONTROL_FAIL)을 분리. "손상 입력이 runner를 verdict 전에 죽여도 gate는 PASS로 해석하지 않는다"는 것이 이 컨트롤의 핵심 가치 — fixture를 억지로 최종 FAIL 판정까지 가게 바꾸면 오히려 이 failure mode를 잃음. 현재 삼중 조건(rc≠0·스위트 실실행·PASS 부재)은 합리적. 보강: `observed=ABORT_BEFORE_VERDICT`·`verdict_present=false` 명시 — "parser가 놓쳤는지/runner가 죽었는지/아예 안 돌았는지"를 future에서 구분 가능. **빈 observed는 수용하지 말고 명시 상태로 교정하되 CA-21 판정 방식은 유지.**

3개 컨트롤의 역할 분리가 명확해짐: **CA-18=semantic FAIL 발급 가능 증명 / CA-21=abnormal termination을 PASS로 오인하지 않음 / positive smoke=semantic PASS 발급 가능 증명**.

## 3. positive smoke — hard fixture 단독 manifest 적절. 단 same-path 필수

lavfi 결정론 fixture+고정 정답 [2,4,6,8]은 positive smoke에 이상적. 최중요 조건: **manifest만 별도이고 실행/판정 코드는 절대 별도여서는 안 됨**(동일 manifest loader→runner→detection→scoring→oracle→qauto recorder — positive 전용 `if control: print("PASS")` 경로가 생기면 control 의미 상실).

CLOSED 조건: rc==0·suite_started·expected_case_count==executed_case_count·final_verdict==PASS·CONTROL_OK 기록·app_commit 일치·driver_sha256 일치·manifest/fixture identity 일치. 가능하면 known-good의 실제 지표(recall=1.0·precision=1.0)도 고정.

**CA-18 scorer 수학 unit control은 CLOSED blocker 아님** — 현재 최중요 미검증은 "이 시스템이 PASS를 발급할 능력이 있는가"이고 positive smoke 하나가 해결. CLOSED 조건: negative semantic 1+·abnormal/fail-closed 1+·positive semantic 1+. 단 **예외**: CA-18과 CA-21이 서로 다른 scorer/oracle이면 CA-21 positive가 CA-18 scorer를 증명 못 함 → 그 경우 CA-18 별도 positive contract test 필요(우리의 경우 실제로 서로 다른 scorer — LATER 항목으로 유지).
