## 1. collision 감지 — canonical hash 비교 방식 충분. 단 역할 분리 권고

같은 run_id 재진입 시 새 payload를 canonicalize해 기존 manifest의 의미상 payload와 비교, hash 동일→IDEMPOTENT_REPLAY·다름→ERROR_PROVENANCE_COLLISION으로 가르는 것은 provenance 관점에서 좋은 계약. 단 역할 분리 권장: **payload_sha256(실행 의미의 canonical hash — run_id·commit/tree identity·phase·fixture/dataset identity·expected/observed·driver_exit_code·record contents·authorization)** vs **manifest_sha256(전체 canonical hash, 자기 필드 제외)**. 재호출마다 달라지는 finished_at·duration_ms·writer timestamp·manifest path는 collision identity에서 제외 — 아니면 동일 실행의 재구성인데 finished_at 차이로 collision 오판 가능(우리는 이미 이 문제를 검증 중 발견·수리했다 — ACTIONS 참조).

canonicalization 계약 최소 고정: UTF-8·object key sort·compact separator·array order preserved·null vs missing 구분·number serialization 규칙. 오류 3종 분리가 이상적: same run_id+same payload_sha256 → IDEMPOTENT_REPLAY / same run_id+different payload_sha256 → ERROR_PROVENANCE_COLLISION / stored manifest_sha256 불일치 → ERROR_MANIFEST_INTEGRITY. 판정: 현재 방식 GO — payload_sha256 분리는 후속 hardening(dataset pin을 밀어낼 P0/P1 아님).

## 2. driver_exit_code 캡처 — 방식 맞음. 함정 3가지

$? 캡처는 반드시 trap의 첫 executable statement여야 함(echo 하나 먼저 찍으면 그 rc가 대신 잡힘). 함정: ①원래 rc를 trap이 덮지 않게 — driver_rc≠0 → 최종 rc 보존 / driver_rc==0 AND manifest write 실패 → provenance failure rc로 실패("테스트 성공+증거 기록 실패=성공"은 계약상 약함) ②set -e 하에서 trap 내부 실패가 뒤 코드를 건너뛰게 하지 않게 set +e 또는 명시적 rc 캡처. signal 경로(SIGKILL·전원)는 EXIT trap이 못 잡음 — 필요 시 termination_kind/signal 필드 추가 가능(이번 회차 필수 아님).

**이번 E2E 필수 테스트 1건**: driver가 의도적으로 exit 23 → manifest driver_exit_code==23 → 프로세스 최종 rc도 23 — 실제 드라이버 경로로 반드시 확인. 판정: 구현 GO, E2E 한 건은 필수 검증으로 유지.

## 3. dataset pin — committed fixture와 생성 입력은 같은 종류의 pin이 아니다

큐 ①의 primary pin은 **커밋된 fixture 파일의 content SHA-256으로 한정**하는 것이 맞음(fixture_id·sha256·size로 pin·실행 전 mismatch fail-closed). 반면 매 실행 생성되는 say/lavfi fixture는 output binary SHA를 dataset identity로 쓰면 안 됨 — macOS 버전·설치 voice·TTS 엔진·ffmpeg 버전·codec·metadata에 따라 동일 명령도 byte가 달라짐. generated fixture는 별도 provenance class: **generator_recipe_sha256(무엇을 생성하라 했는가 — 명령 문자열보다 의미 입력: text/voice/rate/locale, filter expression/duration/sample rate/codec)**·environment_fingerprint(어떤 환경에서)·generated_artifact_sha256(실제 무엇이 생성되었는가).

정책: 정확한 oracle 판정 fixture(silence boundary exact oracle·known-invalid control·frame count oracle 등) → committed immutable fixture 권장. 환경 호환성/smoke(TTS pipeline smoke·ffmpeg availability·codec path) → generated 허용. 큐 ① 복귀 시 1차는 committed fixture content SHA pin+preflight fail-closed까지만, 2차에서 generated에 recipe_sha256 — 처음부터 하나의 dataset_sha256 필드로 통합하면 의미가 모호해짐.
