## 2. --update 자동화 금지 — repository 내부 규칙만으로 완전 구분 불가. 예방보다 탐지가 현실적 목표

자동화가 사람과 동일한 shell/git/filesystem 권한을 가지면 --reason+stage까지 가능하므로 완전한 권한 통제는 불가능. 다음 단계 권장: **dataset-lock-updates.jsonl append-only baseline change journal** — --update 성공 시 fixture_id·old/new SHA-256·old/new git blob SHA·source state(staged|committed)·reason·timestamp·현재 HEAD를 반드시 한 줄 기록. 그리고 check_dataset_pins.sh가 **lock 변경이 있는데 대응 journal entry가 없으면 fail-closed**. 회차 보고에서 신규 journal entry를 무조건 노출. 자동화를 강제 차단하려면 repo 밖 trust boundary(runner command allowlist에서 --update 금지·automation identity에 lock 변경 권한 부여 금지·사람 서명 키 요구)가 필요 — 1인 로컬 자동화라면 journal+보고 강제까지가 비용 대비 최적이고, 향후 merge/release 자동화 시 signature/protected-path로 상향.
