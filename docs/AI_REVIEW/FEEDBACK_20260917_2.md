## 1. update_id 8필드 개행 연결 — 개념은 맞지만 canonical 형식 교체 권고

\n delimiter + reason 내부 개행만 치환하는 방식은 장기 계약으로 약함("0x0A" 문자열과 치환 결과의 충돌 가능·path 등 다른 필드의 개행 가능성·부분 escape 규칙의 예외 증가). 전체 payload를 한 번에 canonical serialization 권장.

더 중요한 변경은 **update_seq**: 8필드만으로 ID를 만들면 정상적으로도 동일 ID가 재발 가능(A→B→A→B에서 마지막 A→B의 reason까지 같으면 첫 번째와 동일) — content hash는 내용은 식별하지만 사건(occurrence)을 식별하지 않음. 분리 구조:

- **update_id = sha256("dataset-pin-update-v2" + fixture_id + update_seq)** — 사건 식별자
- **payload_digest = sha256(canonical_json(path·old/new sha·old/new blob·base_head_commit·source_state·reason))** — 내용 식별자

reason 내부 LF 치환은 삭제하고 JSON serializer escaping에 맡길 것.

## 3. STOP(<10GiB) — 완전 휴면보다 guard-only 상태

| 상태 | 허용 |
|---|---|
| BLOCK | build/test 금지, 저비용 script 작업 가능 |
| STOP | 개발 작업 전부 정지, 최소 disk guard + 상태 보고만 허용 |
