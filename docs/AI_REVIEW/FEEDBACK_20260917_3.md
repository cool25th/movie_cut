## 1. guard-only 회차 운영 — 계약과 일치

실행 권한 이해: PRE-STOP 진입 → 신규 증분 동결 / 용량 일부 회복 → PRE-STOP에서는 벗어날 수 있으나 BLOCK hysteresis가 남으면 build/test 계속 금지 / ≥20GiB 연속 2회 → BLOCK 해제 / ≥25GiB → GREEN·active-soak 계열 가능. **이번 15회차는 "아무 일도 안 한 회차"가 아니라 PRE-STOP 운영 계약을 실제로 검증한 회차로 기록해도 됩니다.**

## 2. 16GiB 판정 — STOP 해제 / BLOCK 유지를 분리하는 것이 더 정확

16GiB는 STOP 영역 아님·PRE-STOP 영역도 아님·BLOCK 해제 조건은 미충족 → build/test와 신규 개발 증분은 계속 금지. 판정을 단일 상태로 표현하기보다 **위험 상태와 실행 권한을 분리**:

```
disk_band: BLOCK · stop_status: CLEARED · pre_stop_status: CLEARED
recovery_state: RECOVERY_PENDING · execution_policy: NO_BUILD_NO_TEST
reason: hysteresis_requires_2x_ge_20GiB · available: 16.00GiB
```

사람용 보고는 짧게: **"STOP/PRE-STOP 해제 · BLOCK 유지"** — 16GiB까지 회복했으나 ≥20GiB 2회 연속 미충족으로 신규 build/test와 개발 증분은 계속 금지. 9→12→16→21GiB 회복 시 상태 전이가 명확해짐. STOP 해제와 BLOCK 해제를 동일 취급 금지 — STOP은 절대 안전장치, BLOCK은 작업 재개 권한으로 서로 다른 축. episodes24h=0도 정상(기존 BLOCK 이어짐)이나 사람 오해 방지로 current_episode_active/current_episode_started_at 필드 유지 권장.
