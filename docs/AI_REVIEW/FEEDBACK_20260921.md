# ChatGPT 피드백 — 2026-09-21 (27회차·driver exit E2E)

> 원문: chatgpt.com 대화(reload 복구 완성본 4,619자) — 발췌 없이 구조만 정리.

이어서 보면, 27회차에서 provenance contract를 닫은 다음 28회차의 핵심은 generated fixture를 기존 committed fixture와 같은 방식으로 취급하지 않는 것입니다. 둘은 provenance 성격이 다르기 때문에 class를 분리하는 게 맞습니다.

## 1. provenance class 최소 2종 분리

- **COMMITTED_FIXTURE**: Git tree에 고정된 바이트 자체가 provenance의 기준.
- **GENERATED_FIXTURE**: 생성 입력 + generator identity + generator version + generation parameters가 provenance의 기준.

generated fixture는 최종 SHA만 고정하면 부족합니다. 같은 출력이 나왔더라도 "어떻게 생성됐는지"가 없으면 재현성과 provenance를 증명할 수 없습니다. 최소 계약:

```
fixture_id
provenance_class = GENERATED
generator_id
generator_version
generator_source_commit
generation_parameters_hash
input_fixture_ids[]
input_sha256[]
output_sha256
generated_at
```

특히 **generator_source_commit과 generation_parameters_hash**가 중요 — binary/script 이름만 기록하면 같은 이름의 generator 코드가 바뀌었을 때 provenance가 무너짐.

## 2. generated fixture identity는 output SHA와 분리

- `fixture_id` = 논리 identity
- `generation_id = hash(fixture_id, generator_source_commit, generation_parameters_hash, ordered_input_sha256)`
- `output_sha256` = 그 generation의 결과 증거

즉 generation_id = "왜 이 결과가 만들어졌는가", output_sha256 = "실제로 무엇이 만들어졌는가" — 두 층 분리.

## 3. update_id 의미론 재사용 금지 — generation event로 분리

현재 update는 A→B dataset 상태 변경. generated fixture는 `inputs + generator + params → output` derivation. generated fixture 변화는 update가 아니라 **GENERATE / REGENERATE / REBASELINE / REPAIR** 이벤트로 분리. generator version 변경으로 output이 바뀐 경우 A→B만 보면 update처럼 보이지만 원인은 g1→g2 — 이 차이를 보존해야 "왜 fixture가 바뀌었는가"를 설명 가능.

epoch 의미론은 재사용 가능:

```
epoch 1
  GENERATE g1 → sha A
  REGENERATE g1 → sha A   # deterministic confirmation
REBASELINE
epoch 2
  GENERATE g2 → sha B
```

단 **regenerate와 rebaseline을 반드시 구분**: regenerate=같은 provenance world 안에서 같은 generation contract 재실행 / rebaseline=provenance world 자체를 의도적으로 변경. generator 코드 변경이 항상 rebaseline은 아님(버그 수정이어도 lineage 유지 가능) — rebaseline은 계속 운영자의 명시적 행위여야 함.

## 4. generated fixture invariant (GEN-01~06)

- GEN-01 generation_id 재계산 일치
- GEN-02 output_sha256 실제 파일과 일치
- GEN-03 generator_source_commit 존재
- GEN-04 모든 input fixture provenance 검증 완료
- GEN-05 input ordering canonical
- GEN-06 동일 generation_id → output_sha256 하나만 허용 — 위반은 단순 mismatch가 아니라 **NONDETERMINISTIC_GENERATION** 상태로 별도 표기 (가장 가치 있는 탐지)

**비대칭 계약 명시**: same generation_id + different output = violation / different generation_id + same output = allowed (generator v1+params A → X, generator v2+params B → X 우연 일치는 오류 아님).
