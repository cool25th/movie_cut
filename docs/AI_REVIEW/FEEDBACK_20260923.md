## 1. CONTRACT_REVISED — 새 "명령"이 아니라 provenance "사건"(audit event)으로

- GENERATE=새 generation identity 생성 / REGENERATE=동일 identity 재현 검증(read-only) / REBASELINE=유효한 계약의 기준을 의도적으로 epoch N+1로 변경. 반면 첫 H1≠H2 때문에 contract를 고친 것은 "기준값 승인"이 아니라 **기존 generator contract의 불충분 발견·정의 수정 사건**.
- 상태 머신: `GENERATE(G1)→REGENERATE(G1)→[H1≠H2]→NONDETERMINISTIC_GENERATION→G1 INVALIDATED→CONTRACT_REVISED(G1→G2)→GENERATE(G2)→REGENERATE(G2) PASS`.
- 불변식 3종: ①NONDETERMINISTIC G1은 정상 복귀 불가(G1은 실패한 역사 그대로 — 재검색에서 PASS처럼 보이면 rewrite) ②CONTRACT_REVISED는 new_generation_id != old_generation_id 필수 ③CONTRACT_REVISED 직후 REBASELINE 금지.
- 권장 필드: old_generation_id·new_generation_id·trigger=NONDETERMINISTIC_GENERATION·h1·h2·cause_class=muxer_metadata|encoder|command|other·old/new_source_commit·revision_summary. **실제 상태 변화는 뒤따르는 새 GENERATE가 담당** — CONTRACT_REVISED는 lock 변경·epoch 증가 금지. "contract defect로 인한 세대 교체"를 기계적으로 질의 가능하게 하는 것이 핵심.

## 3. environment provenance — 3단계 승격 규칙 고정

- **L0 observational**(현재): os_version·arch·ffmpeg_version — journal 기록만.
- **L1 contract dependency**: 결과에 영향 가능성이 구조적으로 높거나 generator가 직접 의존 — ffmpeg binary/version·codec·encoder·muxer·command flags는 **canonical generator contract에 포함 가능**(ffmpeg_binary_sha256+canonical_command까지는 정당).
- **L2 generation identity**: **실제 A/B 증거가 있을 때만** 승격(동일 contract·다른 arch→다른 artifact 실증 시 arch 승격).
- 원칙: **"Observed ≠ causal. Causal ≠ necessarily identity. Identity는 재현성에 실제로 필요한 최소 집합."** — "결과를 만드는 프로그램/옵션은 contract, 실행된 머신 특성은 observation".
- ffmpeg는 version string보다 **실행 binary provenance**(sha256·build configuration)가 더 중요 — journal 관측 권장. software encoder 명시(hardware encoder 미사용)도 중요.

1. identity/manifest consistency(GEN-01) → 2. output integrity(GEN-02) → 3. deterministic relation(GEN-06). 특히 **Mutation C(동일 gen_id+다른 정상 output)가 GEN-02로 잡히면 안 됨** — 파일은 손상이 아니라 identity에 맞지 않는 유효한 별도 결과물. 비결정성 원인 분류도 2종: CONTAINER_METADATA(payload 동일·metadata 불일치 — bitexact로 해결 가능) vs MEDIA_PAYLOAD(decoded 자체 불일치 — ffmpeg/encoder/thread/FP/arch로 조사 확대 — metadata normalization으로 해결된 것으로 처리 금지).
