## 1. hev1 disposition — Apple 최소 재현→MovieCut 경로 4단계 분리

- **주의**: Apple 문서만으로 "모든 hev1 입력이 unsupported"라 단정할 근거는 부족 — hvc1 선호/특정 프로필 요구 ≠ hev1 전면 불가.
- 판정 사다리: **T0** 동일 elementary HEVC bitstream을 sample-entry(hvc1/hev1)만 다르게 remux(재인코딩 금지 — confounder 방지) → **T1** AVFoundation load/decode → **T2** bare AVAssetExportSession → **T3** AVAssetReader→AVAssetWriter 재인코딩 → **T4** MovieCut 실제 pipeline.
- 판정표(6행): T1 실패=framework limitation 후보 / ExportSession 실패+Reader→Writer 성공=우회 가능(BUG) / Apple 최소 harness 성공+MovieCut만 실패=MovieCut 결함 확정 / 호환성 API compatible 반환+실측 실패=inconsistency 기록.
- export 전 기록할 것: formatDescription/FourCC·compatible preset 결과·supportedFileTypes·선택 preset·output type·NSError domain/code·failureReason·recoverySuggestion.
- **disposition rule 고정**: EXPECTED_UNSUPPORTED = documented boundary OR Apple-minimal-harness 실패 + practical fallback 없음 / BUG = MovieCut만 실패 OR supported fallback 존재 OR 선언 범위 불일치.
- **원인 판정과 UX 결함은 분리**: disposition=EXPECTED_UNSUPPORTED라도 "작업이 중단됨"→"이 HEVC 형식(hev1)은 현재 내보내기를 지원하지 않습니다"는 별도 BUG(BUG-CORPUS-01-UX).

## 2. BUG-CA12-03도 동일 lifecycle 계약 — benchmark 증거 신뢰성 연결

- discovered_by(kind: QAUTO/BENCHMARK/id/evidence)는 발견 채널만 다를 뿐 같은 lifecycle: **DISCOVERED→REPRODUCED→ROOT_CAUSED→DISPOSITIONED→FIXED/ACCEPTED_UNSUPPORTED→REGRESSION_PROVED→CLOSED**.
- 프리뷰 dump가 stale하면 benchmark 입력→metric→PSNR/SSIM이 오염 — 영향 가능한 기존 benchmark 결과에 `evidence_status: SUSPECT`+`affected_by: BUG-CA12-03` 연결, 수정 후 재측정으로 `REVALIDATED`.
- `discovered_by`만 말고 **`evidence_affected` 역방향 링크**도 권장 — QA/benchmark/telemetry 어느 경로든 같은 lifecycle 진입.
