## 10-11. seed failure promotion — 의도적 fault injector로 증명

- test-only fault injector: 특정 seed(예: seed=0xDEADBEEF·step=73)에서만 invariant violation. 흐름: random torture→failure 감지→seed+step+command history 저장→**immutable regression fixture 생성→randomized runner 없이 fixture 단독 실행→동일 실패 재현**→fix 후 fixture PASS.
- fixture 최소 필드: fixture_id·origin_seed·failing_step·initial_project_state·command_sequence[0..failing_step]·expected_invariant·discovered_at_commit. 제외: wall clock·machine name·OS patch·runner pid·random counter(저널 관측이면 충분).
- **불변식: regression fixture execution != random generator execution** — fixture가 seed runner를 다시 호출하면 승격이 아님. "stochastic discovery가 deterministic regression asset으로 승격됨"의 증명이 QAUTO-06의 더 큰 자산.

## 12. P3 DSL — 액션 개수보다 semantic contract 먼저

- Action→Plan→Validate→Apply→Undo→Serialize→Replay가 같은 의미 유지. 최소 3계약: ①invalid action = no mutation ②valid action replay = same project state ③action serialization roundtrip = semantic-equivalent — 전 액션 공통화가 breadth보다 우선.
