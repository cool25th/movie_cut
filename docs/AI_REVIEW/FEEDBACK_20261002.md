## 회차별 판정
- **33회차 disk gate**: "현재 상태"와 "작업 시작 허용" 분리가 핵심 성과·LARGE 9.42GiB 실거부로 계약이 제어장치임을 증명. self-test set -e 조용 탈출 사건은 guard 자체보다 **검증기가 실패를 성공처럼 보일 수 있었던 문제** — 향후 self-test는 expected verdict 총계 invariant 필요.
- **34회차 semantic contract**: "명령이 동일 파싱됐는가"가 아니라 **동일 사용자 의도가 동일 semantic plan으로 귀결되는가**를 처음 계약화. 잘못된 명세를 코드에 맞추지 않은 것도 중요.
- **35회차 BLOCK**: 멈춰야 할 때 정말 멈췄는지가 핵심 — GUARD_DEFERRED·build/test 0회·전 클래스 DENIED면 정상 동작. 이 상태에서 wiring을 밀어붙였다면 disk guard 작업 전체가 무의미해졌을 것.
- **36회차 hysteresis**: 세션 중 임시 df 조회를 공식 상태로 승격하지 않은 것 정확. 현재는 "22GiB대다"가 아니라 **BLOCK episode가 아직 종료되지 않았다**가 정확한 표현.

## 1. rc 4 = START_GATE_DENIED 적절 — 유지
2=BLOCK(시스템 상태)·3=STOP(운영 중단)·4=START_GATE_DENIED(작업 클래스 headroom 미달)은 의미이 다름. 추가할 것: **machine-readable reason**(decision=DENIED·reason=INSUFFICIENT_START_HEADROOM·class·required_gib·actual_gib·rc=4). rc namespace는 더 늘리지 말 것 — rc=4+reason enum 유지.

## 2. 클래스 수치 재검토 — "3회 후" 하나로는 부족
재검토 트리거 5조건: ①클래스별 정상 완료 표본 ≥3 ②peak consumption이 budget 70~80% 2회 접근 ③허용 작업이 실행 중 BLOCK/STOP 유발 ④DENIED인데 dry-run 사용량이 현저히 작음 ⑤클래스 내 분산 확대. 실측은 start_free·min_free_during_run·end_free 3값 기록(consumed_peak)·재설정 기준은 관측 최대+안전마진. 현재 1/5/10 변경 근거 없음 — LARGE 9.42 거부 사건이 오히려 10GiB guard의 존재 이유.

## 3. semantic shape — 2층 구조 권장
Level A(topology shape — 현행 extent+volume): replay/idempotence 계약용. **Level B(semantic fingerprint)**: 사용자 의미 필드만 canonical projection(track role·asset semantic id·source range·timeline range·playback rate·enabled/muted·transform·effect·gain·transition — UUID·timestamp·캐시키·내부 id 제외). 34회차 테스트는 Level A 유지·production seed promotion identity가 Level B 사용.

## 4. removeSilence plan/apply 분리 — 정합. 별도 계약 추가
"removeSilence plan은 content-derived edit coordinates를 포함하지 않는다"·apply는 analyze→derive concrete edit set→validate→**atomic apply(분석 중간 실패 시 partial deletion 없음)**·동일 project bytes+동일 analysis version→동일 edit set.

## 5. seed promotion 사양 확정안
- **identity는 의미 키**(failure_class·semantic_operation·minimal_state_signature·expected_invariant — seed=7/73은 provenance가지 identity 아님)+**semantic_version 필드**(의미론 변경 시 v1 retired→v2 current).
- **dedup**: 1 fixture ← 여러 seed observation append(새 fixture 생성 금지).
- **minimization 불변 3종**: 동일 failure class·동일 invariant·RNG-free 독립 재현("같은 stack trace" 불필요 — 같은 semantic defect면 충분)+**causal signature same**(command type·state transition·failing validator 좁은 fingerprint).
- **fail-fast**: failure classification 직후 canonical identity lookup→기존 identity면 KNOWN_FIXTURE_REGRESSION 즉시 종료. **IDENTITY_CONFLICT 별도 hard failure**(identity match인데 fixture replay PASS+live FAIL — collision/stale/coarse 3가지 가능성·매우 가치 큰 신호).
- **promotion 전제**: pre-fix FAIL/post-fix PASS 쌍 필수. seed7/step73은 사실상 이미 충족.
