## 1. 40회차 recovery close와 41회차 wiring 분리 — 승인
23.61+28.23 모두 ≥20·간격 26h 이내 → 2/2 hysteresis 충족으로 BLOCK episode 종료 근거 충분. **41회차를 "예약된 실행"으로 보지 말 것**: 진입 시점 START_GATE MEDIUM이 다시 DENIED면 즉시 GUARD_DEFERRED — **RECOVERY_CONFIRMED는 BLOCK episode 종료 증명일 뿐, 내일의 MEDIUM 허가를 선지급하지 않는다**(§8/HANDOFF에 명시 권장).

## 2. INFRA-CHAT-01 — 분류 상향+조사 트리거
- 분류: 단순 "전송 실패"보다 **INTERMITTENT_RECURRENCE**·상태는 OPEN/INTERMITTENT/WORKAROUND_ACTIVE(resolved로 닫았다 열기 금지).
- 현재 최적 정책 유지: 전송 가능 시 즉시 flush·실패 시 로컬 원장 누적·제품 회차는 막지 않음.
- **조사 트리거 4종**(발생 시에만 devtools/clean profile 조사 승격): ①7일 내 동일 장애 2회 추가 ②연속 48h 전송 불가 ③reload 외 특정 조작으로 재현성 발생 ④누적 보고가 리뷰 lifecycle 지연 시작. 그 전에는 devtools 조사 자체가 역전.
- **전송 채널 신뢰도 계측**: attempted_at·result·failure_class·recovery_method·recurrence_after_reload 최소 필드(KPI 아님 — nuisance→방해 요인 전환 판정용 증거).
- 다음 재발 시 증거 5종만: reload 전후 차이·새/기존 대화 차이·clean profile 재현·입력은 되는데 send만 실패인지·network 요청 발생 여부.

## 3. Genspark — "독립 관점의 보조 감사"(cold reviewer)
- 원장·ID·상태 전이는 하나, **리뷰어만 복수**. CA 항목에 sourceReviewer·firstSeen·evidence·disposition·status·verification 추가.
- 동일 문제 중복 지적 시 신규 CA 금지 — 기존 CA에 **independent corroboration**으로.
- **주기는 이벤트 기반/저빈도**(큰 기능 완료·외부 리뷰 5~10건 누적·베타 직전·1~2주 간격) — 매 회차 동일 자료 금지(독립 검증→중복 생성기 전락).
- **프롬프트 분리**: Genspark엔 최근 상태 요약+불변 제약+현재 open CA만 — 과거 reasoning은 덜 줌(독립성).
- **Reviewer invariant**: "Reviewer는 action을 생성할 수 있지만 상태 전이를 직접 확정하지 않는다" — 원장 OPEN→VERIFIED→CLOSED는 항상 evidence contract가 결정.
- **리뷰 결과 분류 5종**: NEW_DEFECT / EVIDENCE_GAP / CORROBORATION / ALREADY_SATISFIED / REJECTED — backlog 부풀어 오름 방지·reviewer count≠품질.
