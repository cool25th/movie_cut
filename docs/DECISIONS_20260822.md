## Q13 (미결정 상신) — MetricKit 방침 (STAB-07, 2026-08-31 상신)

> **상신 상태 — 사용자 결정 대기.** 이 섹션은 제안만 담는다. 결정 전 구현·문서 정정 없음.

**충돌**: `REQUIREMENTS.md` §13.8(2026-07-30 App Store 배포 승격 시 신설)은 "MetricKit 최소 도입 — 크래시·행·전력 지표를 수집한다"고 요구하나, `AppLog.swift`(Mac)는 "MetricKit / remote telemetry are intentionally NOT introduced — 완전 온디바이스 포지셔닝"을 명시하고 iOS도 MetricKit 참조가 전무하다. 하나를 고쳐야 한다.

**사실 관계**(Apple 문서 기준 — 페이지가 JS 렌더링이라 요지 확인):
- MetricKit은 **앱 콘텐츠·미디어·PII를 전송하지 않는다** — 시스템이 수집한 성능 수치(행률·런치·메모리 등)와 익명화된 진단(크래시·행 콜스택)만.
- 성능 payload는 기기에서 수집·식별 정보 없음. 진단 payload는 **사용자가 설정→개인정보보호→분석 및 개선 "개발자와 Analytics 공유"를 켠 경우에만** 개발자에게 전달(Apple 경유 일일 집계·기기 내 심볼리케이션) — 즉 **OS 수준 옵트인·기본 꺼짐**이며 §13.10의 "외부 처리는 명시·기본 OFF" 원칙을 이미 만족하는 구조.
- 플랫폼: iOS 13+·**macOS 12+** — 배포 대상(Q3: macOS 14 유지)과 호환. 단 전력 등 일부 지표의 macOS 가용성과 App Store Privacy Label 영향은 도입 시 실험 확인 필요(제안 단계에서 단정하지 않음).

**옵션**:

| 안 | 내용 | 대가 |
|---|---|---|
| **A — 온디바이스 구독 한정 채택 (제안)** | `MXMetricManager` 구독 + 수신 payload를 AppLog(OSLog)에 기록하는 것만. 앱에 네트워크·서버 코드 추가 0. 크래시·행 가시성은 Apple 익명 집계 경유로 확보 | AppLog의 "완전 온디바이스" 문구를 "앱 기능·미디어 처리의 완전 온디바이스(진단은 Apple 익명 경유)"로 정정 |
| B — §13.8 요구 폐기 | MetricKit 줄을 "OSLog 구조 로깅(이미 구현) + 사용자 수동 진단 공유"로 대체 | App Store 배포 후 크래시 가시성이 사용자 수동 의존 — Phase 3-A 베타 "중대 데이터 손실 0건" 검증의 증거 원천 약화 |
| C — 베타 이후 재검토 | 현상태 유지, 불일치는 "일시 유보"로 명시 | 결정 지연되는 동안 §13.8 위반 지속 |

**권고: 안 A.** 근거: ①전송되는 것에 미디어·편집 데이터가 없음 — "무료·오프라인" 차별화(§14 경쟁 표)는 기능·과금·클라우드 이야기이므로 실질 손상 없음 ②Phase 3-A 베타 안정성 증거에 직결 ③구현 비용 수십 줄·서버 없음 ④요구(§13.8)를 지키면서 프라이버시 실질을 유지하는 경로가 이것뿐.

**결정 시 파생 작업**(결정 후 1증분, 루프 실행 가능): iOS+Mac `MXMetricManager` 구독·AppLog 기록 추가, AppLog 주석 정정, §13.8 체크박스화, (선택) 베타 빌드 payload 수신 실증. **안 B 결정 시**: §13.8 문구 대체 + AppLog 주석에 근거 추가.
