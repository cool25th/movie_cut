## 0. 고정 순서 (방향 문서 §2 로드맵 라인)

**기존 엔진 UI 완성(1단계✓) → 오디오 믹싱 기본선(G-25✓) → 손떨림 보정(G-24) → 모바일 실기기(유보) → 효과 탐색·선별 콘텐츠(G-28) → HDR 공개 → ML 스템(G-26 B)**

1단계 완료로 다음 미완拓扑는 **G-24 손떨림 보정 v1** — 방향 문서가 "효과 볼륨 확대보다 우선"으로 명시. G-26은 G-25 그래프 위에 올라가는 계열이므로 G-24와 병렬 가능하나 증분 원자성原则上 순차 진행.

## 1. 증분 사이클 (1단계 패턴 승계)

- 증분 1개 = 원자 단위 = 커밋 1개(+docs 커밋). 커밋 직전 `verify_gate.sh` 5단계 전부 통과 필수.
- 완료 판정은 측정 증거만(골든 픽셀 + 파리티 + E2E + null test). 자기 보고 수치 금지.
- 게이트 2회 연속 실패 시 즉시 중단·보고.
- 15~20% 경계 정리 배분(1단계 루프 회차들이 증명한 원칙).

## 2. G-24 손떨림 보정 v1 — 증분 전개 (우선)

백로그 §0.5 DoD: **잔류 흔들림 중앙값 50%↓·크롭 중앙값 ≤15%·심각 워블 ≤3%·장면 전환 오류 0건**. 지표는 §6.4 AI 보완(하위 5%·아티팩트 라벨) 적용.

| 증분 | 산출 | 게이트 |
|---|---|---|
| **P2-G24-1 (Core)** | 측정 인프라: `StabilizationMetrics`(잔류 흔들림[프레임 간 변위 중앙값]·크롭 비율·워블 지수·장면 전환 오류 카운트의 순수 수학) + `StabilizationFixture`(결정적 흔들림 픽스처 — 합성 sine 움블 + 임계 워블 구간 + 장면 전환 2회, SHA-256 게이트) + 단위 테스트 | swift test(측정 수학의 해석값 고정) |
| **P2-G24-2 (Core)** | `SceneChangeProvider` 재활용한 장면 분할 → 세그먼트별 등록 시드 결정 | 장면 경계 ±2프레임(픽스처 ground truth) |
| **P2-G24-3 (Core)** | Vision 등록(VNGenerateOpticalFlowRequest 또는 homography 추정) → 프레임별 변환 행렬 + confidence | 합성 움블에서 행렬 회수(알려진 ground truth와 ±10% 이내) |
| **P2-G24-4 (Core)** | 경로 평활화(이동 평균 또는 Savitzky-Golay) + adaptive crop(잔류 변위 중앙값 ≤15% 클램프) | 평활화 전후 잔류 흔들림 비(DSR 수치) |
| **P2-G24-5 (App)** | CI warp(`CIPerspectiveTransform` 또는 `HIGravityWarp`) 렌더 체인 편입(프리뷰+출력+iOS) + confidence fallback(낮으면 바이패스 — 조용한 강등 아님·명시적 로그) | 파리티 시나리오 신규(스태빌 게이트)·골든 |
| **P2-G24-6 (E2E)** | 하니스 게이트(`MOVIECUT_UITEST_STABILIZE=1`) + E2E 섹션 + **DoD 수치 실측**(픽스처 기준: 잔류 50%↓·크롭 ≤15%·워블 ≤3%·장면 전환 오류 0) | E2E 2회 동일 |

**함정 레지스터(G-24)**: ① Vision 등록 프레임 레이트 의존(30fps 고정 픽스처로 시작) ② 크롭 과다(≤15% 클램프가 아니면 화면 잘림) ③ confidence 문턱 민감(낮으면 미스태빌·높으면 바이패스 과다 — 픽스처로 문턱 고정) ④ 장면 전환 경계에서 워프 점프(세그먼트 분할이 선행 방어) ⑤ iOS Vision 가용성(시뮬레이터 E2E로 조기 확인).

## 3. G-28 효과·템플릿 브라우저 (G-24 완료 후)

**착수 전제**: `EffectCostProfile` 스키마 확정(PERFORMANCE_SLO 신설 — 렌더 비용 등급[ms/프레임 실측]·메모리 피크·GPU/CPU 구분). 개수 KPI 폐지·검색 성공률·재사용률 KPI.

증분: ① EffectCostProfile 스키마+기존 이펙트 프로파일링 실측 → ② 브라우저 UI(검색·미리보기·즐겨찾기·파라미터) → ③ 템플릿 브라우저(G-19 계열 확장) → ④ KPI 측정 창구(하니스).

## 4. G-26 오디오 프로세서 단계 B (G-28 병렬 또는 이후)

Apple AU 우선(컴프레서·리미터·리버브) — 그래프의 자리 노드(§5 nodeKind)가 이미 존재하므로 스키마 변경 없이 구현만. 게이트: **LUFS ±0.2LU·true-peak ±0.2dB**(§8 엄격 게이트의 자연 확장 — 미터·null test 재사용).

증분: ① 컴프레서(AVAudioUnitCompressor) 그래프 노드 구현 → ② 리미터+리버브 → ③ 트랩 스트립·프리셋·디-이서 초기 → ④ 게이트 실측(±0.2LU).
