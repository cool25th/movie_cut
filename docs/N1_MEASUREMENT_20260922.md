## 측정이 발견·수리한 실제 결함

**1차 실측 FAIL — T1 p95 = 180.64 ms(예산 3.6배 초과)**: 원인은 원샷 API `matches(for:in:)`가 **쿼리마다 코퍼스 전체를 재구축**하는 것(900카드 정규화+스팬 수학). 검색창이 키 입력마다 재발화하는 실사용에서 30분 프로젝트에서 180ms 지연은 체감 마찰이다.

**수리**: `TranscriptSearchIndex.Corpus`(build-once/search-many) 타입 신설 + Mac VM에 타임라인 키 캐시(`transcriptCorpusCache` — Timeline Equatable 비교로 변경 시에만 재구축). 원샷 API는 Corpus 위의 convenience로 유지(기존 호출자 호환). **수정 후 p95 4.78 ms — 37.8배 개선.** 구축 비용은 타임라인 변경당 1회(176 ms)로 분리 축(T1b)으로 사전등록·측정.

이 경과는 "임계값 사전등록 → 정직한 FAIL → 구현 수리 → 재측정 PASS" 규율의 사례로 남긴다(부분 통과=가짜 수정 금지).
