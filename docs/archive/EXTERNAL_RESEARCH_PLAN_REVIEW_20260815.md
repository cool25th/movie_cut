# 영상 편집기 "MovieCut" — CapCut / Final Cut Pro급 품질 달성을 위한 리서치·계획 검수 요청

- **작성일**: 2026-08-15
- **요청 성격**: 코드 접근 없이 이 문서만으로 판단할 수 있도록 자족적으로 작성됨. 제품의 로드맵·리서치 전략에 대한 제3자 검수를 요청
- **목표**: CapCut(조작성·SNS 영상 UX)과 Final Cut Pro(출력 품질·전문성)에 준하는 편집 경험을 달성하는 것. **음향(오디오) 품질을 포함**

---

## 1. 제품 개요와 제약 조건

- **제품**: MovieCut — 네이티브 비선형 영상 편집기 (+ 이미지 카드뉴스 제작 기능). 데스크톱(macOS) 주력, 모바일(iOS) 2순위
- **기술 스택**: Swift 네이티브, AVFoundation / CoreImage / AVAudioEngine / Apple Vision(온디바이스 AI). 직접 코덱 구현은 하지 않음(AVFoundation 우선)
- **원칙·제약** (외부 조언 시 반드시 고려해 주세요):
  - **완전 오프라인, 네트워크 권한 0** — 모든 AI 처리는 온디바이스이거나 명시적으로 실패. 서버 연동형 기능은 원칙적으로 불가
  - 무료, 계정 없음, 클라우드 동기화 없음, 공동 편집 없음 (1인 창작 도구)
  - 배포는 Mac App Store 단독
  - 현재 렌더링은 CoreImage 기반 (Metal 직접 구현은 성능 근거가 생길 때까지 보류 중)
- **벤치마크**: CapCut = 조작성·기능 범위 기준 / Final Cut Pro = 출력 품질·전문성 기준
- **전략**: "CapCut 패리티는 바닥이고 목표는 상회" — ProRes 마스터 출력, (계획 중인) HDR, 전문 컬러 그레이딩, 무료·오프라인으로 차별화

## 2. 현재까지 달성한 수준 (측정 증거 포함)

### 2.1 검증된 코어 편집 엔진
- 모든 편집 동작이 개별 "명령"으로 기록되는 구조로 **무제한 undo/redo 보장** (되돌리기 무결성 테스트 통과)
- **프리뷰와 최종 출력이 동일한 렌더링 코드 경로를 사용** → 12개 핵심 시나리오(분할, 속도 곡선, 자막, 배경음악, 필터+마스크, 이미지 혼합, 리플 삭제 등)에서 프리뷰↔출력 픽셀 오차를 매일 밤 자동 검증 (오차 기준: 채널당 평균절대오차 ≤ 2.0, 길이 오차 ≤ 1프레임)
- 프로젝트 자동저장·크래시 복구(자동화 게이트로 검증), 데이터 형식 마이그레이션 4세대 운영
- 기기 발열 상태에 따른 4단계 프리뷰 품질 강등으로 발열·프레임 드롭 방지

### 2.2 비디오 편집 — 구현 + 측정 완료
- **기본 편집**: 트림/분할/리플 삭제, 전문 편집 도구(slip/slide), 자석 타임라인, 클립 그룹, 마커(비트 마커→챕터), 프레임 단위 정확한 이동, 키보드 셔틀(J/K/L)
- **합성**: 멀티트랙 + 레이어 순서, 블렌드 모드 12종, 마스크 6종(페더/반전), 크로마키(스포이드 추출+색 번짐 억제), AI 인물 배경 제거(프리뷰는 고품질 속도, 출력은 정밀 모드), 복합 클립(여러 클립을 하나로 묶고 내부 진입 편집)
- **모션**: 키프레임 엔진(보간 5모드 내장), 배속 0.25–4배, 속도 곡선(램프) 편집기, 광학플로우 슬로모션(인접 프레임 오차 0.0015로 측정 검증), 리버스, 정지화면, Ken Burns(이미지 줌/팬)
- **컬러**: 기본 보정(밝기/대비/채도/색온/틴트) + **3-way 컬러휠(lift/gamma/gain, ASC-CDL 방식)** + HSL 8밴드 조정 + 톤 커브 + `.cube` LUT 임포트, 스코프 3종(히스토그램/파형/벡터스코프), 자동 화이트밸런스
- **AI/Vision**: 모션 트래킹(실제 영상 IoU 평균 0.79 측정), 자동 리프레임, 장면 감지, 자동 컷 편집, 하이라이트 추천
- **텍스트**: 자막 번인, 텍스트 애니메이션 12종, 타이틀 템플릿 14종, 스티커 22종, **온디바이스 음성인식 자동 자막**(단어 타이밍 저장), SRT 입출력

### 2.3 오디오 — 구현 + 측정 완료
- 멀티 오디오 트랙, 영상에서 오디오 분리 추출, 파형 표시
- 클립별 볼륨/페이드(프리뷰·출력 동일 램프 적용)
- 5밴드 이퀄라이저(실시간 + 출력용 오프라인 렌더, 주파수 스펙트럼 비교로 검증)
- 스펙트럴 노이즈 감소(측정: 5.17dB 개선, 음성 보존률 0.913)
- 자동 덕킹(배경음악 자동 볼륨 낮춤 — 측정: 12.04dB 감쇠), 비트 감지(온셋 검출기, 비트→마커→챕터)
- 보컬 분리(중앙채널 위상 상쇄 방식의 DSP — ML 아님), TTS(텍스트 음성 변환), 보이스오버 녹음, 오디오 단독 추출

### 2.4 출력과 성능
- 코덱/형식: H.264, HEVC, **ProRes 422**, GIF, 정지 이미지, 오디오 단독, SNS 규격 프리셋(9:16, 16:9, 1:1 — 실 출력 파일을 ffprobe로 검증), 비트레이트 직접 지정 경로
- **성능 측정값**: 4K 출력 속도가 실시간의 0.99배(Release 기준, 목표 1.2배 이내), 메모리 최대 237MB(목표 4GB 이내), 1080p 프리뷰 프레임당 5.5ms(60fps 예산의 33%)
- 저해상도 프록시 생성·재생 워크플로(데스크톱만)

### 2.5 품질 관리 체계
- 테스트 1,134개 통과(단위/통합), 골든 픽셀 테스트(기대 화면과의 픽셀 단위 비교), 실 미디어 파일을 넣는 종단간 출력 테스트 33개 기능 섹션, 랜덤 입력 안정성 퍼즈 55 시나리오, 크래시 복구 게이트, UI 회귀(스크린샷 유사도), 매일 밤 자동 성능·품질 게이트 CI
- **운영 원칙**: "코드가 존재한다고 완성이 아니다", 모든 '동등/우수' 판정은 프리뷰+출력 동시 증거 필요, 자기 보고 수치 금지. 과거 과대 평가 6건을 스스로 발견해 하향 조정한 이력이 있음

## 3. 객관적 자기 평가

- **CapCut 대비 실사용 체감 완성도 65–72%** (자체 평가, '상회' 선언은 근거 확보 전까지 금지 상태)
- **강점**: 코어 편집 정확성(프리뷰=출력 구조적 보장), 성능·메모리 효율, 되돌리기 무결성, 컬러 엔진 깊이, 검증 인프라
- **약점**: 콘텐츠 볼륨(효과·템플릿·오디오 처리 폭), 고급 기능의 UI 미완(엔진은 있는데 사용자가 접근 못함), 오디오 프로세싱 품질, 모바일(iOS) 런타임 검증 부재

- 사용되지 않는 실험 코드 약 1,300줄 정리 대기

## 5. 외부 검수 요청 — 검토해 주셨으면 하는 8가지 질문

1. **우선순위 프레임**: 체감 완성도 65–72% → 90% 이상으로 올리는 데 사용자 가치 기여가 가장 큰 갭은 무엇이라고 보는가? (후보: 이펙트 볼륨 확대 / 오디오 프로세식 고도화 / 고급 기능 UI 마무리 / 모바일 검증·패리티) 현재 전략 "CapCut 패리티 바닥 + Pro 출력 차별화"는 유지 가능한가?
2. **오디오 전략**: 팬·컴프레서·리버브·믹서를 (a) AVAudioEngine+자체 DSP 확장, (b) 표준 AudioUnits/서드파티 DSP, (c) 온디바이스 ML 중 어느 조합으로 갈 것인가? 온디바이스 원칙(네트워크 금지) 하에서 ML 스템 분리는 현실적인가 — 어떤 모델/접근이 존재하는가? SNS 영상 문법에서 "좋은 소리"는 무엇이며 어떻게 객관 측정하는가?
3. **컬러/HDR**: 8-bit SDR → 10-bit HDR 전환은 언제 하는 것이 맞는가, 비용·리스크는? Final Cut Pro급 색 관리(색역/트랜스퍼 함수) 도입의 단계는?
4. **콘텐츠 생태계**: 이펙트·템플릿·전환을 수백 종으로 늘리는 방법으로 (a) 자체 제작, (b) 외부 큐레이션/라이선스, (c) 플러그인 시스템(서드파티 제작자 유입) 중 무엇이 승부수인가? 음악/효과음 카탈로그의 현실적인 조달·라이선스 방식은?
5. **화질 처리 상한**: Apple 프레임워크(AVFoundation/Vision/CoreImage) 조합으로 손떨림 보정 등 FCP/CapCut 체감 품질에 도달 가능한가? 한계가 있다면 Metal 직접 구현이나 서드파티 엔진을 도입할 시점의 판단 기준은?
6. **모바일 전략**: "구현됐지만 미검증"인 모바일 부채를 갚는 자동 검증 인프라를 신규 기능보다 먼저 만들어야 하는가? 아니면 데스크톱 완성도 우선이 맞는가?
7. **성능 전략**: 현재 CoreImage 기반이 성능 목표를 여유 있게 충족(프레임당 5.5ms/16.6ms 예산) 중이다. 이펙트 볼륨이 수백 종으로 늘어난 뒤에도 유지 가능한 판단인가? Metal 전환 재검토의 트리거는?
8. **검증 방법론**: 현재 "프리뷰↔출력 픽셀 오차 + 시나리오 게이트" 방식의 맹점은? 특히 오디오 품질을 객관화하는 측정 체계(현재는 스펙트럼/RMS/SNR 수준)의 확장 방안은?
