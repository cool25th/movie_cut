## 1. 구조적 문제 (지시서 §7 재확인)

1. **동작 신호가 0이다.** 소스 문자열의 존재만 확인하고, 실제 동작은 검증하지 않는다.
2. **정상 리팍터가 테스트를 깨뜨린다.** Task B(함수→계산 프로퍼티)와 Task E(세션 리셋→커맨드 경로)가 정확히 이 사례였다. 두 경우 모두 올바른 리팩터가 3~1개 테스트를 빨갛게 만들었다.
3. **결함을 고정한다.** `IOSParityMatrixStaticContractTests.swift:56-57,61`이 미구현 iOS 기능을 `!contains`로 잠갔다. 기능을 구현하면 테스트가 깨지므로 개발을 적극적으로 방해한다.

## 2. 분류 방침 (3분류)

### (a) 삭제 — 동작 신호가 없고 유지비만 있는 것

- **`docs/*.md` 산문을 단언하는 38개 파일의 대부분.** 문서 문장은 테스트 대상이 아니다. 문서 오타/표현 변경이 테스트를 깨뜨리며, 이는 문서가 코드에 종속됨을 의미한다(역방향).
- 문서의 *구조적 사실*(예: "매트릭스에 N개 defer 항목이 있다")만 검증하는 소수는 문서 자체 검증 스크립트로 분리하거나 (b)로 승격 고려.

### (b) 동작 테스트로 승격 — 실제 기능을 다루는 것

- **Core processor / 알고리즘 단언.** `IOSParityMatrix`의 긍정 단언(`ColorCorrectionPixelProcessor.apply` 포함) 등은 문자열이 아니라 *골든 픽셀 비교*로 검증해야 한다. `GoldenPixelHarness`(`Tests/MovieCutCoreTests/Support/GoldenPixelHarness.swift`)가 이미 이 패턴을 확립했다 — software `CIContext` + `assertRendererFunctional()`로 headless에서 픽셀 assertion이 조용히 skip되던 문제를 해결한 선례.
- 승격 순서: 렌더 프로세서 > 시간 매핑 > 오디오 분석. Task C(`ClipTimeMapping`)가 동작 테스트의 좋은 예시다.

### (c) 유지 — 문자열 검사가 실제로 적절한 소수

- **아키텍처 경계 잠금.** "이 UI 마커가 코어 서비스를 호출하지 않는다" 같은 경계 검사(R305의 `!serviceSource.contains(uiMarker)` 일부). 단, 부정 단언이라도 *경계 방향*(UI→Core 침투 방지)이면 의미가 있다.
- 단, 이 카테고리는 엄격히 선별해야 한다. "기능이 없다"를 잠그는 부정 단언은 절대 유지하지 않는다.

## 3. 부정 단언(`!contains`) 처리 원칙

> **결함을 잠그는 부정 단언은 전부 제거한다.** 미구현 상태는 문서(`docs/PLATFORM_PARITY_MATRIX.md`)로 추적하면 충분하다.

두 종류의 `!contains`를 구분해야 한다:

| 종류 | 예 | 처리 |
|------|-----|------|
| **결함 고정** (기능 부재 잠금) | `!iosCompositor.contains("TransitionPixelProcessor.apply")` | **제거** — 기능 구현을 막음 |
| **경계 방향** (침투 방지) | `!viewModel.contains("ExportEngine")` (UI가 코어 서비스를 직접 부르지 않음) | **사례별 판단** — 아키텍처 경계면 유지 |

판단 기준: 부정 단언이 **"무언가가 존재하면 안 된다"**면 제거 대상, **"무언가가 다른 계층에 침투하면 안 된다"**면 유지 후보.

## 4. 이번 세션에서 수행한 것

- `IOSParityMatrixStaticContractTests`에서 **결함 고정 부정 단언 3건 제거** (`:56,57,61`). 긍정 단언(공유 프로세서 존재)과 문서 단언(매트릭스에 미구현 상태 기록)은 유지.
- 본 분류 방침 문서 작성.

## 5. 후속 세션 권장 작업 (우선순위)

1. **부정 단언 전수 조사** (225건). 위 분류 기준으로 "결함 고정" vs "경계 방향"을 나눈다. 결함 고정은 제거, 경계 방향은 주석과 함께 유지.
2. **`docs/*.md` 단언 38개 삭제** (a 카테고리). 문서 산문은 테스트 대상이 아님.
3. **렌더 프로세서 긍정 단언을 `GoldenPixelHarness` 골든 비교로 승격** (b 카테고리). 가장 가치가 크다.
4. 분류 완료 후 **실제 커버리지 변화 보고**. 테스트 수는 줄어들 것이며, 줄어든 만큼이 원래 가짜 신호였다. 줄어든 후에도 main은 green이어야 한다.

## 6. 주의사항

- StaticContract 대량 삭제 시 **일시적 커버리지 수치 하락**은 정상이다. 숫자가 줄어드는 것 자체가 목표가 아니라, *가짜 신호 제거*가 목표다.
- 승격(b) 작업은 `GoldenPixelHarness` 패턴을 반드시 따른다 — headless skip 함정을 재현하지 말 것.
- 문서 단언 삭제 전, 해당 문서가 *여전히 유효한지* 먼저 확인한다. 죽은 문서를 테스트가 살려두고 있었을 수 있다.
